# External reference memory enables continuity across models

## Observation

Useful lessons held only in one assistant's conversational memory are difficult to reuse when the model, account, product surface, or vendor changes.

## Interpretation

A portable external reference layer can preserve generalized experience without making any one assistant the permanent owner of system knowledge.

## Decision relevance

Store reusable principles and routing evidence in inspectable versioned artifacts with provenance and uncertainty. Let different models consume the same reference layer while project canon remains separate.

## Limits

External memory can itself become stale or polluted; it needs curation, supersession, and clear non-authoritative status.
